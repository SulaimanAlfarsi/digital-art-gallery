# Riwaq Art

Riwaq Art is a bilingual digital art gallery built with Next.js. It presents a curated collection of historic artworks through an animated, responsive interface in English and Arabic.

**Live website:** [https://riwaq-art.vercel.app](https://riwaq-art.vercel.app)

The current collection contains **41 artworks** across **8 art movements**. Artwork images are loaded from public remote sources, while titles, artists, dates, categories, and supporting information are stored locally as JSON.

## Website Features

- English and Arabic interfaces with automatic left-to-right and right-to-left layout switching
- Saved language preference using browser `localStorage`
- Responsive desktop and mobile navigation
- Animated page transitions powered by GSAP
- Framer Motion animations for menus, filters, cards, and project folders
- Artwork category filtering
- Artwork cards with colors extracted dynamically from each image
- Responsive image marquee on the home page
- Interactive art-movement folders on the Explore page
- Animated canvas footer built from an Open Peeps sprite sheet
- Open Graph and Twitter metadata for social sharing
- Remote image proxy with validation and caching

## Pages

### Home (`/`)

The landing page introduces Riwaq Art with:

- An animated hero containing the gallery name, description, and a link to the full collection
- A continuously moving marquee made from artwork images
- The first five artworks from the collection as featured works
- The shared navigation, language control, page transition, and animated footer

### Artworks (`/artworks`)

The main gallery displays all artworks in a responsive grid. Visitors can filter the collection by:

- Renaissance
- Northern Renaissance
- Baroque
- Impressionism
- Post-Impressionism
- Romanticism
- Ukiyo-e
- Surrealism

Filter changes animate the grid without reloading the page. Each card displays the localized artwork title, category, artist, and year. On hover or keyboard focus, a colored SVG transition reveals the details. The transition colors are sampled in the browser from the artwork image through the image proxy.

### Explore (`/explore`)

The Explore page groups the collection into interactive folders by art movement. Each folder:

- Shows preview images from that category
- Displays the number of artworks in the group
- Identifies representative artists
- Opens visually on hover with layered spring animations

Folder counts and previews are generated directly from the English artwork dataset, so they update automatically when artworks are added or removed.

## Shared Interface

### Navigation

The navigation links to Home, Artworks, and Explore. At the top of a page it appears as a full navigation bar. After the visitor scrolls more than 100 pixels, it changes into a floating menu button. Mobile layouts use the menu button from the start.

### Language Support

The language button switches between English (`EN`) and Arabic (`AR`). The selected language is stored under `riwaq-art-language` in browser `localStorage` and restored on later visits.

Switching language updates:

- Page copy and navigation labels
- Artwork titles, artists, categories, and dates shown on gallery cards
- Art-movement names and descriptions
- The document `lang` and `dir` attributes
- The font used for Latin or Arabic text

English interface translations are defined alongside Arabic translations in `src/lib/i18n-client.tsx`. Localized artwork records are stored separately in `src/data/artworks-ar.json` and matched to English records by `id`.

### Page Transitions

Internal navigation is wrapped by `next-transition-router`. GSAP animates two full-screen SVG strokes before the route changes and removes them after the next page enters.

### Footer

Every page uses the same footer. It contains gallery copy, navigation links, copyright text, and an animated canvas crowd. The crowd is generated by splitting `public/images/peeps/all-peeps-2.png` into sprite cells and animating the characters across the canvas.

## Artwork Data

The primary collection is stored in `src/data/artworks.json`. Every record uses this structure:

```json
{
  "id": 1,
  "title": "Mona Lisa",
  "artist": "Leonardo da Vinci",
  "year": "1503",
  "category": "Renaissance",
  "country": "Italy",
  "museum": "Louvre Museum, Paris",
  "image": "https://example.com/artwork.jpg",
  "description": "A short description of the artwork."
}
```

The Arabic collection in `src/data/artworks-ar.json` must use the same IDs. Keep both files aligned so every English artwork has an Arabic equivalent.

### Adding an Artwork

1. Add a unique record to `src/data/artworks.json`.
2. Add its translated record with the same `id` to `src/data/artworks-ar.json`.
3. Use an existing category, or add the new category to `categoryMeta` in `src/lib/folder-projects.ts`.
4. For a new category, also add its English and Arabic labels and descriptions in `src/lib/i18n-client.tsx`.

The home marquee, artwork filters, and Explore folder counts are all derived from these data files.

## Image Proxy API

`GET /api/image-proxy?url=<encoded-image-url>` fetches remote images for browser-side color extraction.

The endpoint:

- Requires a valid `http` or `https` URL
- Rejects responses that are not images
- Returns upstream errors when an image cannot be loaded
- Revalidates fetched images every 24 hours
- Sends a one-day public cache lifetime with a seven-day stale-while-revalidate period

Example:

```text
/api/image-proxy?url=https%3A%2F%2Fexample.com%2Fpainting.jpg
```

## Local Development

### Requirements

- Node.js 20.9 or newer
- npm
- An internet connection during installation/build and to load remote artwork images

No environment variables or external database are currently required.

### Install and Run

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Commands

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the Webpack development server |
| `npm run build` | Create an optimized production build |
| `npm run start` | Run the completed production build |
| `npm run lint` | Run ESLint across the project |

## Production

Create and run a production build with:

```bash
npm run build
npm run start
```

The image proxy is a server route, so deployment must provide a Next.js-compatible Node.js or serverless runtime. A purely static export will not support the proxy without replacing that functionality.

The default metadata uses `https://riwaq-art.com` as its canonical metadata base. Update `metadataBase` in `src/app/layout.jsx` if the production domain changes.

## Design and Accessibility Notes

- Artwork cards are keyboard-focusable and expose localized image alternative text.
- Filter buttons expose pressed state through `aria-pressed`.
- Navigation and language controls include accessible labels.
- The interface includes responsive layouts and dark color-scheme variables.
- English uses IBM Plex Sans; Arabic uses IBM Plex Sans Arabic.
